# TSK-25 Playwright test for WebGUI live updates via SignalR (Done)

Add a Playwright GUI test covering UST-2 live-update behaviour without a live .NET backend. SignalR HTTP endpoints are mocked so no real backend is required.

**This addresses UST-2 (Live updates):**
> updates generated by the bot during interaction with the Emulator ... automatically appear in the GUI player without manual page refresh.

## Acceptance criteria

- New test file `tests/gui/live-updates.test.ts`.
- Mock SignalR HTTP endpoints (`/hubs/session-updates/negotiate` negotiate response and the hub connection route) via Playwright `page.route`, and mock `GET /test/sessions/{sessionId}/updates`, consistent with `mockBackendEndpoints`. No network to `localhost:5134`.
- Provide a way to emit a `NewUpdate` SignalR message to the connected client (e.g. by driving the mocked hub route or by invoking the client-side `HubConnection.on("NewUpdate")` handler through the page).
- USC-2.1 test: open a real session with offset not at the end (e.g. offset 1 of 3), emit a `NewUpdate` signal, and verify the new update appears in UpdateBrowser's list but is **not** checked, **not** visible in MessengerScreen, and the offset text is unchanged.
- USC-2.2 test: open a real session at End (all 3 checked), emit a `NewUpdate` signal, and verify the new update **is** checked, **is** visible, and the offset text becomes `Offset 4 of 4`.
- Alternative flow test: when scrolled to the bottom, a new update scrolls into view; when not scrolled to the bottom, scroll position is preserved.
- All backend interaction mocked (no network to `localhost:5134`).
