# TSK-24 WebGUI Player live updates via SignalR (Done)

Make the Player automatically reflect new updates arriving from the bot without a page refresh, per UST-2 USC-2.1 / USC-2.2. Uses the `@microsoft/signalr` client to connect to the `/hubs/session-updates` hub.

**This addresses UST-2 (Live updates):**
> updates generated by the bot during interaction with the Emulator to automatically appear in the GUI player without manual page refresh.

## Acceptance criteria

- Add a SignalR hook (e.g. `useSessionUpdates(sessionId)`) that:
  - builds a `HubConnection` to `<backend>/hubs/session-updates` when a real session is selected,
  - joins the session's SignalR group (`JoinSession(sessionId)`) after connecting,
  - listens for the `NewUpdate` message,
  - on `NewUpdate`, refetches `GET /test/sessions/{sessionId}/updates` and reconciles the Player state (updates array + offset) without remounting MessengerScreen/UpdateBrowser state unnecessarily,
  - leaves the group and stops the connection when the selection changes or the component unmounts,
  - reconnects on unexpected disconnect; errors are handled without crashing the Player (show existing "Failed to load updates." path on refetch failure).
- USC-2.1: if the current offset is less than the previous updates.length (not all updates checked) when the signal arrives, the newly arrived update is appended to the list but is **not** checked in UpdateBrowser, **not** visible in MessengerScreen, and the offset is unchanged.
- USC-2.2: if all updates were checked before the signal (offset === previous updates.length, or there were no updates), the newly arrived update **is** checked, **is** visible in MessengerScreen, and the offset becomes the new updates.length.
- Alternative flows (scroll): if the player container was scrolled to the bottom before the update arrives, scroll to the bottom again after the update; otherwise preserve the current scroll position (do not scroll).
