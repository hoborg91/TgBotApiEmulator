# TSK-22 SignalR hub for live session updates (Done)

Add a server-side SignalR hub so the WebGUI can receive live update notifications for a session without polling the backend. SignalR is used instead of raw WebSockets so the client automatically falls back to other transports (Server-Sent Events / long polling) when WebSockets are unavailable, and SignalR handles reconnection and heartbeats.

**This addresses UST-2 (Live updates):**
> "I want updates generated by the bot during interaction with the Emulator to automatically appear in the GUI player without manual page refresh."

## Acceptance criteria

- `SessionUpdatesHub : Hub` (Application or Controllers layer) exposing methods for clients to join/leave a per-session group (`JoinSession(TgSessionId sessionId)`, `LeaveSession(TgSessionId sessionId)`).
- `IUpdateBroadcaster` interface (Application layer): `BroadcastAsync(TgSessionId sessionId)` — sends a signal to all clients in the session's SignalR group.
- `UpdateBroadcaster` singleton implementation wrapping `IHubContext<SessionUpdatesHub>`; `BroadcastAsync(sessionId)` calls `Clients.Group(sessionIdValue).SendAsync("NewUpdate", ...)`.
- SignalR hub registered in `Program.cs` (`builder.Services.AddSignalR()`) and mapped at `/hubs/session-updates` via `endpoints.MapHub<SessionUpdatesHub>("/hubs/session-updates")`.
- `UpdateBroadcaster` registered as a singleton in `Program.cs`.
- The WebGUI client interprets the `NewUpdate` signal as "a new update arrived" and refetches updates via the existing REST `GET /test/sessions/{sessionId}/updates`.
- Broadcasting is fire-and-forget: a failure to send to one client must not prevent sending to other clients in the same group.
