# TSK-23 Wire update notifier into SignalR broadcast (Done)

When an update is recorded in emulator mode, wake connected SignalR GUI clients for that session so the Player can show live updates.

**This addresses UST-2 (Live updates):**
> updates generated by the bot during interaction with the Emulator ... automatically appear in the GUI player without manual page refresh.

## Acceptance criteria

- `UpdateNotifier.Notify(sessionId)` (called after an update is persisted in emulator mode) also triggers `IUpdateBroadcaster.BroadcastAsync(sessionId)` so subscribed SignalR clients are signalled.
- Existing `UpdateReader.WaitForUpdateAsync` one-shot waiter behaviour is unchanged: `Notify` still completes the TCS waiters used by `getUpdates`/assert long-polling.
- Emulator-mode recording paths (`BotController.SendMessageAsync`, `BotController.SetMessageReaction`, `EmulatorController.MessageAsync`) trigger the broadcast via the existing `Notify` path — no duplicate call sites.
- End-to-end: record an update in emulator mode → a SignalR client joined to that session's group receives a `NewUpdate` message.

## Affected files

- `src/TgBotApiEmulator/Application/UpdateNotifier.cs` (inject + call `IUpdateBroadcaster`)
- `src/TgBotApiEmulator/Application/IUpdateBroadcaster.cs` (created in TSK-22)
- `src/TgBotApiEmulator/Program.cs` (ensure `IUpdateBroadcaster`/`UpdateBroadcaster` are resolvable by `UpdateNotifier`)
